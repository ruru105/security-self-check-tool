# 作品6:セキュリティ公開前チェックツール(Security Self-Check Tool)

AIにコードを書いてもらった(いわゆる「バイブコーディング」)あと、公開・納品する前に「最低限ここだけは確認しよう」というセルフチェックを行うPythonツールです。

bandit・pip-audit・detect-secrets という、信頼されているOSSの静的解析ツールを使って自動チェックを行い、結果を日本語のExcelレポートにまとめます。あわせて、自動では判断しきれない項目を含む**100項目の手動チェックリスト**も同じレポートに収録します。

このツールが示すのは「気づきのきっかけ」です。不備をあげつらうことが目的ではなく、公開前に一度立ち止まって確認するための道具としてお使いください。最終判断はご自身で行ってください。誤検知・見落としの可能性もあります。

## 主な機能

- Pythonコードの危険なパターンを検出(bandit): SQLインジェクション、コマンドインジェクション、`eval`の使用、弱い暗号・ハッシュの使用など
- 依存ライブラリの既知の脆弱性(CVE)を検出(pip-audit): `requirements.txt` に書かれたライブラリをチェック
- APIキー・パスワードなど秘密情報の直書きを検出(detect-secrets)
- 自動検出結果を重要度別に色分けして、日本語のExcelレポートに出力
- 自動では判断しきれない項目を含む、100項目の手動チェックリストを同梱(8カテゴリに分類)
- テストコード(`test_*.py` 等)は自動的に除外し、無関係な検出(ノイズ)を減らす

---

## 判定ルール

自動チェックの重要度は3段階です。

| 重要度 | 内容 |
|---|---|
| 🔴 重大 | bandit「HIGH」/ pip-auditで検出された既知の脆弱性(CVE) |
| 🟡 警告 | bandit「MEDIUM」/ detect-secretsで検出された秘密情報らしき値 |
| 🔵 参考 | bandit「LOW」 |

## チェックリストの構成(100項目・8カテゴリ)

自動チェックでカバーできるのは、100項目のうち24項目が目安です(bandit・pip-audit・detect-secretsで部分的に検出できる可能性がある項目)。残りは自分の目で確認する項目として、カテゴリ別に整理しています。

| カテゴリ | 項目数 | うち自動チェックの目安 |
|---|---|---|
| 1. 秘密情報・認証情報の管理 | 15 | 8 |
| 2. 入力値検証・インジェクション対策 | 15 | 5 |
| 3. 認証・認可 | 15 | 1 |
| 4. 依存ライブラリ・サプライチェーン | 10 | 2 |
| 5. 設定・環境 | 15 | 3 |
| 6. ログ・エラー処理 | 10 | 1 |
| 7. 通信・暗号化 | 10 | 4 |
| 8. データ保護・プライバシー | 10 | 0 |
| **合計** | **100** | **24** |

## 出力ファイル

実行すると、Excelファイルを作成します。ファイル名を指定しなかったときは、次の名前で作成します。

`security_report.xlsx`

Excelレポートには次の3シートを出力します。

| シート名 | 内容 |
|---|---|
| 検査結果サマリー | 検査対象、検査日時、重要度別の件数、総合判定 |
| 自動チェック結果 | bandit・pip-audit・detect-secretsが検出した項目の一覧(重要度順) |
| 手動チェックリスト(100項目) | カテゴリ別の100項目。確認欄・対応のヒント・自動チェック対象の目安つき |

## 出力例

付属のデモ用サンプル(`sample_project/`)には、わざとよくある問題を仕込んでいます。これを検査すると、次のように検出されます。

- bandit: SQLインジェクション(文字列結合によるSQL組み立て)、シェルインジェクション(`shell=True`)、`eval`の使用、弱いハッシュ関数(MD5)の使用など 8件
- pip-audit: 古いバージョンの`requests`(2.6.0)に含まれる既知の脆弱性 5件
- detect-secrets: APIキー・パスワードの直書き 3件

同じコマンドを、実際に公開済みの他5作品に対しても実行し、結果を確認しています(2026-10-23時点)。

| 検査対象 | bandit | pip-audit | detect-secrets |
|---|---|---|---|
| 作品1:CSVチェッカー | 0件 | 0件 | 0件 |
| 作品2:シフト違反チェッカー | 0件 | 1件 | 0件 |
| 作品3:やること抜けチェッカー | 1件 | 0件 | 0件 |
| 作品4:つきあわせ | 0件 | 0件 | 0件 |
| 作品5:給料明細ビューア | 0件 | 0件 | 0件 |

検出された2件は内容を確認済みです。

- 作品2の1件: 開発・テスト時にのみ使うライブラリ(pytest)の既知の問題(PYSEC-2026-1845)で、配布される本体のコードやライブラリには影響しません
- 作品3の1件: SQL文の組み立て方法に対する指摘ですが、実際に組み込まれているのはコード内で固定された列名のみで、外部からの入力は安全にプレースホルダ(`?`)経由で渡しています。誤検知と判断しています

このように、自動チェックで検出があった場合でも「検出=危険」と即断せず、内容を確認した上で判断することが大切だと考えています。

## 動作環境

- Python 3.9以上
- bandit / pip-audit / detect-secrets / openpyxl(下記インストール手順を参照)

---

## インストール

```bash
pip install -r requirements.txt
```

---

## 使い方

```bash
python security_check.py <検査したいプロジェクトのフォルダ>
```

まずは付属のサンプルで試せます。

```bash
python security_check.py sample_project
```

出力するExcelファイル名を変えたい場合は `-o` オプションを使います。

```bash
python security_check.py my_project -o my_project_report.xlsx
```

---

## 自動テスト

```bash
pytest
```

チェックリストの整合性(100項目あるか、カテゴリが正しいか)と、サンプルプロジェクトに対するレポート生成が壊れていないかを確認します。

---

## 現在の制限

- 自動チェックの対象はPythonコードと`requirements.txt`のみです。他の言語・フレームワーク固有の問題は検出できません
- 自動チェックは「気づきのきっかけ」であり、誤検知・見落としがあり得ます。最終判断はご自身で行ってください
- 100項目の手動チェックリストのうち、自動チェックがカバーするのは一部(24項目が目安)です。残りは自分の目で確認してください
- このツールはセキュリティ上の問題を網羅的に保証するものではありません。公開前の最低限のセルフチェックとしてお使いください
